Scope: production Rust and embedded SQL throughout crates/. Reviewed timestamp

Count: 28 guard/query sites: 22 SQL statements (25 timestamp predicates) and

A statement with multiple timestamp predicates counts as one site.

SQLx 0.9's postgres chrono encoder uses num_microseconds() since the PostgreSQL
epoch. Modern application timestamps are therefore truncated on every SQL bind;
a SQL WHERE timestamp = $n is not comparing nanoseconds with microseconds.
The Rust wake comparison bypassed that encoding. The public wake_pet boundary
now uses the single pinchora_db::timestamp helper. No migration is needed.

Production impact: both Discord pet::wake and web_player_depth::wake_pet fetch
pets from PostgreSQL immediately before passing pet.needs_at. Neither supplies
a newly generated nanosecond timestamp as the guard. Thus the logs do not show
Linux users unable to wake pets; this was a latent production API defect exposed
by the test retaining its write timestamp. The other three failures were exact
assertions against unrepresentable nanoseconds. Fixtures now use database
precision; every original assertion remains. The new explicit .958061832Z
regression exercises raw input, a one-microsecond stale guard, single-use/free
wake behavior, exact read-back, and SQL trip/care guards on macOS as well.

Roblox lock cause and fix:
VerificationLease::drop spawned Redis deletion without awaiting it. Completed
verify/check/unverify handlers could reply while the lease remained held. A real
user repeating a click could receive 'Another Roblox update is running' after
completion. This was timing dependent, not Linux-specific and not test-only.
These handlers now prepare their response, await token-checked release on both
success and error paths, then reply. Drop remains cancellation/failure cleanup;
the lease TTL and heartbeat behavior are retained. Role sync also awaits release
before returning, and privacy cleanup releases after the database deletion.
The Roblox simulator no longer sleeps 30 ms to wait for these unlocks. Actual overlapping work
still returns busy. The lease regression checks immediate reacquisition and
ensures an old owner cannot delete its replacement; the existing English/Turkish
single-use/expired assertion remains unchanged.

CI now runs on main and merge/** pushes and uses cargo test --workspace
--no-fail-fast. Validation is deliberately scoped; the full workspace suite was
not run. PINCHORA_TEST_MIX_SECS=60 is supplied to each requested test run, but
that knob is consumed by the separate locks test binary, not db or simulate.
Other VerificationLease users still use asynchronous Drop cleanup and can have
similar brief retry windows; they are outside the reported Roblox flow.
